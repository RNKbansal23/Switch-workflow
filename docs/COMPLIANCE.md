# Hackathon requirements and evidence checklist

Checked against the [official rules](https://www.wemakedevs.org/hackathons/switch/rules), [challenge](https://www.wemakedevs.org/hackathons/switch), and [schedule](https://www.wemakedevs.org/hackathons/switch/schedule). Public requirements can change; the published pages govern participation. This checklist is not an eligibility or legal determination.

## Participant-owned entry tasks

- [ ] Register personally using one accurate identity; verify age and jurisdiction eligibility.
- [ ] Confirm team size and any employment/institutional restrictions.
- [ ] Complete entry and prize verification personally if requested.
- [ ] Read ownership/licensing terms and dependency obligations before submission.

No automation in this repository registers, submits, votes, or creates participation identities. AI agents are used only to develop and demonstrate the workflow. No claim is made that the participant has completed the unchecked tasks above.

## Project traceability

| Requirement | Planned proof | Current state |
| --- | --- | --- |
| Switch central to collaboration | Actual support/engineering room handoffs and shared context | Template and role contracts ready; live run pending |
| Person and agent do useful work | Report → patch → independent checks → human decision | Local executable flow implemented; live agent run pending |
| Work built during event | Git history and dated development record | Work started in this workspace during the stated event window; preserve commits |
| Reproducible result | Standard-library CLI, fixed input, real Git revisions, tests | Local tests and labelled rehearsal available |
| Explainable use of AI | Agent instructions, acceptance policy, honest limitations | Documented |
| Repository, demo, README | Final links and fresh-checkout verification | Repository content available locally; final demo/submission pending |
| Rights and confidentiality | Original code, synthetic customer data, dependency/source attribution | Synthetic fixtures labelled; participant must complete final review |

## Evidence and presentation rules we impose

- Distinguish fixture rehearsal from a live agent run.
- Keep reviewer actions human-operated in the live demo; test reviewer identities exist only in automated tests.
- Show actual test output and full candidate commits.
- Say 'local patch accepted' rather than claiming production deployment.
- Report measured counts only; do not invent savings or success percentages.
- Preserve the existing hackathon research and its unresolved-source notes.

## Optional tracks

The primary target is the Business Workflow track. Treat voice, blog, and social awards as optional additions with their own evidence in the event's current materials. The core contribution track requires assigned Switch issues; this project repository is not itself a contribution PR to Switch.

## Before submitting

- [ ] Verify current live registration/submission form fields.
- [ ] Confirm accessible repo and video URLs.
- [ ] Record Switch Console/server/provider versions and successful live setup.
- [ ] Capture a genuine person-to-agent request, agent handoff, executed verification, and human review.
- [ ] Run tests and fresh-checkout setup.
- [ ] Review sample logs and exported templates before publishing.
- [ ] Submit before November 7, 2026, 11:59 PM IST and save the confirmation.
